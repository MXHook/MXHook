# User Story: Understand Release and Changelog Process

**System:** MXHook
**Personas:** OSS Go Developer

---

## User Goal

As an OSS Go Developer, I want to understand how releases and changelogs work so that
my merged PR is correctly reflected in the next release notes.

---

## Context

Contributor merges NATS adapter PR. Wants to know: when will it be released? How is
the changelog generated? Is there a CHANGELOG.md to update manually?

---

## Acceptance Criteria

- [ ] `docs/RELEASING.md` exists with: versioning policy, release cadence, how to cut a release.
- [ ] CHANGELOG maintained: either auto-generated from Conventional Commits or manually curated.
- [ ] Release via goreleaser (`.goreleaser.yaml` present); GitHub Release created automatically.
- [ ] Tag format: `v<semver>`; patch for fixes, minor for new features, major for breaking.
- [ ] Contributor's PR included in release notes if commit message follows Conventional Commits.

---

## Implementation Notes

### Pseudocode / Architecture

```pseudocode
release process:
  1. maintainer tags: git tag v0.x.y
  2. goreleaser:
     - builds binaries (linux/mac/windows, amd64/arm64)
     - creates GitHub Release
     - generates release notes from Conventional Commits since last tag
  3. release notes sections:
     feat:  → Features
     fix:   → Bug Fixes
     docs:  → Documentation
     chore: → Maintenance (often excluded)

CHANGELOG.md:
  option A: auto-generated by goreleaser from git log
  option B: manually curated in PR; goreleaser links to CHANGELOG section
```

### Key Files/Modules

- `.goreleaser.yaml`: release config (present)
- `docs/RELEASING.md`: release guide (to be created)
- `.github/workflows/release.yml`: release CI trigger

---

## E2E / Verification Checklist

- [ ] Read .goreleaser.yaml; understand output artifacts.
- [ ] Read RELEASING.md; understand tagging + release flow.
- [ ] Verify contributor's `feat:` commit appears in auto-generated release notes.
- [ ] Dry-run: `goreleaser release --snapshot --clean`; verify build succeeds.
